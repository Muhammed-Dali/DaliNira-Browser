## Baseline and audit

Started with a clean working tree at M3-B4
3fd726c92cc4502099170648ada37871bd4e1914. Validation and final-audit.json
record this pre-commit HEAD.
Inspected GeckoEngineView, GeckoSession, GeckoBackend, BrowserWindow tab/window
closure, application quit/exit, native host beforeunload/document guards,
presentation parking, asynchronous creation/adoption, and the existing tests.

Root cause: requestClose interpreted every result other than
beforeunload-confirmation-required as permission. A timeout, cancellation,
unknown error, or invalid reply could remove the Qt view while its host document
remained live. The destructor then sent a discard-enabled close. A second close
while the first was pending also returned permission. Creation callbacks could
force-close a tab whose widget disappeared. Shutdown unconditionally requested
discard. Additionally, shutdown acknowledgements changed session state before
correlation/deadline validation, and hostPid retained its value after process exit.

## Exact fix

- Tab closure is fail-closed. Unknown errors, cancellation, timeout, failed IPC,
  malformed or stale replies deny closure. Pending/unbound views deny duplicate
  or premature closure. Terminal callbacks are single-shot and reset pending state.
- A close request captures the logical view, session generation and native
  document identity before dispatch. All protocol-3 closes carry that identity;
  the host checks it before mutation. Missing discard identity is refused.
- Replies must match the request command and required tab identity. Successful
  close replies and beforeunload challenges must echo the exact document ID.
  A success acknowledgement alone is insufficient: Qt waits for authoritative
  tab-closed state, bounded by five seconds. Already closed documents, or a
  definitively exited host, allow disposal without inventing user consent.
- Confirmation is tied to the requesting document and checked again after the
  nested dialog loop. QPointer guards prevent access to widgets deleted inside
  confirmation callbacks. Native unload refusal or changed identity denies close.
- Widget destructors only release presentation/registration; they send no close
  or discard. Host tabs created after their widget disappears remain session-owned
  and are not placed into the empty-tab spare pool. Late/cancelled creations are also excluded from the spare pool. Each creation
  listener finishes with its own request.
- GeckoBackend now owns guarded asynchronous session shutdown, including every
  live host tab, even one without a widget. Initial and confirmed shutdown carry
  the complete document snapshot. The host checks registry size and identities
  before consent, then again after awaiting native unload checks. Replies echo
  the snapshot and are correlated before the session becomes Stopping.
- Gecko window-close and application Quit events use that guarded shutdown.
  Denial preserves windows and documents. The presentation surface stays attached
  during a refused window close. Direct QCoreApplication::exit, which bypasses
  Quit events, cannot fall through to teardown: main resumes the application
  event loop if guarded shutdown fails. Final process cleanup is separate from
  permission and runs after acceptance or definitive host death.
- hostIsRunning uses actual QProcess state rather than the retained identity PID.
  Old generations/replies cannot authorize a replacement session's shutdown.

The protocol-3 document binding is a coordinated adapter/host strengthening.
Older clients omitting required close/shutdown identities fail closed against
this host. Protocol-1/2 handling, authenticated IPC, URL restrictions, sandbox,
Fission, certificate validation, updater policy, and production GPU preferences
are unchanged. No Gecko source patch or runtime rebuild was needed.

## Remaining risks and limits

External process termination, forced object teardown of the whole backend, and
operating-system shutdown can still destroy documents; they cannot manufacture
user consent or restore unsaved data. Ordinary application/window exit is guarded.
Destroying just a view retains its live document in the session, but does not
implement automatic UI restoration for an orphan; guarded session shutdown still
includes it. Cancellation/timeout cannot roll back a legitimately applied native
close; the adapter requires authoritative closure evidence or keeps the Qt tab.

Real-desktop confirmation, X11 embedding/focus, and real WebKit GUI rendering were
not rerun because authorization excludes desktop GUI tests and Xvfb. Their prior
M3-B4 validation is not claimed as a new result. Current headless tests do not
reverify hardware WebRender; production GPU settings were not changed.
